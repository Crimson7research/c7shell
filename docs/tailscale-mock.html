a
Expires in 18 months is disabled text, directly above the action that fixes it. Always shown, never gated on a threshold — I'd proposed hiding it until <14 days, which would have meant it was invisible for its entire development life.
b
Three sections, and the grouping is just a group-by on UserID. Tailscale puts every tagged node under one synthetic user — User[uid].LoginName == "tagged-devices", display name Tagged Devices — so the sections fall out of the data with no special casing. Labels are the app's own: My Devices, Tagged Devices, Other Users.
c
Only Other Users needs an owner line — in the other two the owner is implied by the heading. c7-test-2 sees 10 / 8 / 2.
e
Click a row, the IP goes to the clipboard. Live in this mock — try it. Feedback stays in the row: a popover has nowhere else to put it, and a toast for a copy would outlive the panel that triggered it.
d
Names are not unique. C7-LAP-G1157C6M and localhost each appear twice in your tailnet, which is why every row carries its IP.

a
The recommendation is a server answer, not a measurement. GET /localapi/v0/suggest-exit-node returns 73 bytes — an ID and a name, no metric. Eligible peers carry CapMap: {"suggest-exit-node": null}.
b
none is a checked row, not an absence. Radio semantics: you pick egress, you don't toggle a feature.
c
allow local network access is scoped here, not in global settings — it's prefs.ExitNodeAllowLANAccess, and it's the control for the LAN blackhole you flagged when we put Tailscale on the VM.
d
The republish trap does not apply here — the architecture already solved it. docs/architecture.md mandates collections as QAbstractListModel with stable rows: "A model updates rows in place, so a list view never rebuilds the row someone is typing a password into." Rows key on NodeID. And nothing polls: /localapi/v0/watch-ipn-bus streams change notifications, so the backend is event-driven like NmNetworkBackend on PropertiesChanged.

CAPTURED LIVE — THE REAL SHAPE

ExitNodeStatus carries no hostname:
{"ID":"nWqTQFdqb121CNTRL","Online":true,"TailscaleIPs":["100.111.18.72/32","fd7a:...:1248/128"]}

So the name in the alert has to be joined back: ExitNodeStatus.ID → the matching Peer[].ID. And those IPs carry /32 and /128 masks while the peer's own TailscaleIPs are bare, so they will not compare equal without stripping. ExitNodeStatus.Online is the field that drives the blocked state.

c
Issue(s) Detected… and Current Issues are the app's own strings — a counted row that opens a list, which is where health goes. That amber warning is live on c7-test-2 right now and is your deliberate anti-nullroute config, so it still needs suppressing or it warns forever on the only machine this runs on.
