## Decisions

V1. **A view test is a JSON header plus a Rust body.** The header sits in
  `tests/fixtures/tailscale/views/<id>.json`: `format`, `id`,
  `requirements`, `tag`, `evidence`, `clauses`, `deferred`, `body` and
  `on`, with the scenario format's meaning. `body` names a Rust function in
  `plugin/tests/tailscale-parity/src/views/bodies/`. Why: the suite's checks
  are imperative. They compare positions, keep a width or a delegate and
  compare it later, open menus and click inside them. A JSON step language
  for that would be a second programming language. The header keeps what
  the evidence checks and the runner already read: requirements, tag,
  declarations with failing ids and actual values.

V2. **The views come from the reference.** `build-reference.sh` also
  extracts `quickshell/c7shell/` from `a38dbca`, and `--views` prints that
  directory. The runner reads it from `C7_VIEWS_DIR`.

V3. **Each child builds its own import tree** under its private root:
  #286's view files copied from `C7_VIEWS_DIR`, the stand-ins from
  `plugin/tests/tailscale-parity/qml/standins/`, and the theme stand-in with
  its `PaletteStore` generated in Rust from the views' `palette.json`. The
  stand-ins are written from the requirements (R-QML-25, R-QML-27 and
  traceability's "Stand-in" rows), not copied from Quickshell.

V4. **One generic view driver,** `qml/views-driver.qml`: a window holding
  `StatusPill` and `TailscalePopover`, answering `Probe` commands. It knows
  no `ts-` name. Objects cross to Rust as handles, numbered by identity, so
  "the same delegate" is "the same handle". Commands: `get`, `set`,
  `invoke`, `find` (descendants, by `objectName`), `layout` (the layout
  barrier: five `forceLayout()` passes over the popover and the slot),
  `calls` (the stand-in's recorded calls, taken) and `focus`.

V5. **Every mutation is followed by the layout barrier.** The Rust side
  runs `layout` after each `set` and each `invoke`, so every visibility,
  text, colour or width read follows it, as the spec's "Two halves" rule
  says. A recorded-call read happens when the click returns; the barrier
  records no call.

V6. **A check records; a lookup errs.** `check(id, holds, actual)` records a
  failing id with its actual value and goes on. A lookup that cannot
  proceed (no element of a name, two where one is needed) is an error,
  unless the clause is about that count, in which case it is a check.

V7. **Any `.qml:` line in a view child's log is an error,** for R-QML-26's
  "no warning naming a `.qml` file" and R-QML-27.

V8. **Self-tests first,** on a stub view tree under `selftest/views/`:
  the driver's commands, handle identity, the layout barrier, the `.qml:`
  rule and every runner verdict.

## Implementation notes

1. **Four more deferred halves.** evidence.json gives #309 the view halves
   of R-GROUP-06, R-WATCH-13, R-WRITE-09 and R-UI-15 as deferred clauses.
   #307's and #308's scenarios already name those requirements, so the
   coverage check passed for them with no view test.
   `every_requirement_of_309_has_a_view_test` counts view tests only, and
   the scope is 30 requirements: the 26 above and these four.
2. **Tags follow what runs.** The view halves of R-CONN-15 and R-WATCH-13
   run only clauses #286 meets (the dimmed slot), so they are `parity`
   though their requirements are `fix`, as in #307 and #308. R-UI-16's view
   half is the one `fix` view test: #286's connect tip puts the write's
   refusal ahead of the no-daemon phrase
   (`TailscalePopover.qml:322-327`), so two Texts explain the failures.
3. **The driver gained `now`, `date_ms`, `watch` and `fired`** for R-QML-06
   (the wall clock the view reads, and the 12-hour margin) and R-QML-25
   (the models' row signals), each with its self-test.
4. **R-QML-10's no-process clause is a static read** of #286's
   `PeerRow.qml` and `CopyMenu.qml` from `C7_VIEWS_DIR`, as the spec
   allows (`tests/test-native-boundary.sh` scans `quickshell/c7shell` on
   this branch, not #286's).
5. **Delegates are found through `itemAtIndex`,** as the original's
   `rowOfNodeId()` does, not through `children`: a delegate the view has
   released stays a child until its deferred delete runs, and the driver
   runs no event loop between commands.
6. **Table C gained a View tests column** and the R-QML rows (145 in all).
   `every_check_of_the_qml_suite_maps_to_a_view_test` reads the
   requirements Table B maps `tests/tailscale-qml-test.qml` to and fails on
   any no view test names, unless evidence.json makes it `phase3-only` with
   a reason (R-GROUP-11 and R-WRITE-10).
7. **The bite check mutates #286's views,** not the bodies: each mutation
   of a copy of `C7_VIEWS_DIR` must make its view test fail at a value.
   One candidate was equivalent under the spec: dropping the recommended
   row's own query filter changes nothing R-QML-19 reads, because each
   exit row filters itself too. It was replaced by a mutation of the
   list's match function.

## Review fixes

The code review approved with minor findings. Each was fixed:

1. R-QML-20 read a row as live when its title was not dimmed, whatever its
   hover; dimming and hover are now checked separately (a non-hoverable
   live row now fails it).
2. R-UI-16 counts the explanations with the exit and with the settings
   sub-card open too. #286 shows the same two in each, declared.
3. The four deferred-half headers no longer list their own clause as
   deferred; they name the backend half and the #307 or #308 tests that
   run it.
4. `peer_row` reads visible rows only, so a released delegate cannot be
   the row checked.
5. The `.qml:` rule skips the child's result line, whose values may name a
   `.qml` file.
6. `watch` resets its count, as its doc says.
7. R-GROUP-06's move control requires alpha last as well as bravo first.
8. Every check records what it observed, never a fixed `true`, `false` or
   `null`; the duplicated slot checks share `dimmed_for` and
   `cross_shown`, and the refusal text check is one helper.
